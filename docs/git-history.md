# Работа с Git на примере StudyFlow

Этапы лабораторной работы №2: от первого файла программы до объединения веток, решения конфликта и выпуска версии.

## 1. Репозиторий и первая версия

Репозиторий `Maddog8181/StudyFlow` создан с `README.md` и шаблоном `.gitignore` для Python. После этого он клонирован на компьютер:

```powershell
git clone https://github.com/Maddog8181/StudyFlow.git
cd StudyFlow
```

Первое изменение программы — файл `src/main.py`, который выводит `Hello, World!`. Изменение сохранено [отдельным коммитом](https://github.com/Maddog8181/StudyFlow/commit/db61e070bda0b333e80e5974a99070770332f522) и отправлено в `main`.

## 2. Ветка feature-1 и первый запрос на объединение

В `feature-1` добавлены основные действия с учебными заданиями:

- добавление задания с названием, предметом и сроком;
- список по дате сдачи;
- отметка выполнения по номеру;
- сохранение записей в JSON;
- демонстрационный список без изменения личных данных.

Изменения объединены с `main` через [запрос №1](https://github.com/Maddog8181/StudyFlow/pull/1). Описание запроса объясняет назначение изменений и их проверку. До объединения проверены добавление, вывод списка, отметка выполнения и сообщения об ошибках при пустом названии и неизвестном номере задания.

## 3. Две ветки от общей версии

После объединения первого запроса от одной версии созданы `feature-2` и `hotfix`.

В `feature-2` добавлена сводка количества заданий. Одновременно изменена строка заголовка демонстрации:

```python
print(f"StudyFlow — задания и сводка на {DEMO_DATE}.")
```

В `hotfix` уточнена та же строка, чтобы пользователь понимал назначение демонстрационного режима:

```python
print(f"StudyFlow — демонстрация на дату {DEMO_DATE}; данные примера не изменяются.")
```

**Конфликт создан намеренно для лабораторной работы.** Это учебная имитация параллельной работы: две ветки независимо меняют одну строку. Конфликт действительно возникает при объединении этих изменений в Git.

## 4. Конфликт и его решение

Сначала `hotfix` объединён с `main`. После этого [запрос №2](https://github.com/Maddog8181/StudyFlow/pull/2) из `feature-2` потребовал разрешения конфликта в `src/main.py`. Конфликт проверен на GitHub и в локальной копии.

Для получения актуальных изменений и их объединения в своей ветке выполнены команды:

```powershell
git fetch origin
git switch feature-2
git merge origin/main
```

Git не выбрал один из двух заголовков автоматически. В файле остались обе версии с отметками конфликта. Отметки удалены вручную, а итоговая строка получила вид:

```python
print(f"StudyFlow — демонстрация на дату {DEMO_DATE}; личные данные не изменяются.")
```

Функция сводки сохранена. После проверки программы исправленный файл добавлен в коммит, ветка отправлена на GitHub, а запрос №2 объединён с `main`.

## 5. Версия v1.0.0

После объединения изменений и проверки создаётся аннотированная метка:

```powershell
git tag -a v1.0.0 -m "StudyFlow 1.0.0: учебные задания и сроки"
git push origin v1.0.0
```

Метка фиксирует определённую версию кода. На её основе оформляется [выпуск v1.0.0](https://github.com/Maddog8181/StudyFlow/releases/tag/v1.0.0) с описанием возможностей и архивом исходных файлов.

## Основные команды

| Команда | Значение |
|---|---|
| `git clone` | Скачать репозиторий вместе с историей |
| `git status` | Посмотреть состояние файлов и текущую ветку |
| `git add` | Выбрать изменения для следующего коммита |
| `git commit` | Сохранить выбранные изменения в локальной истории |
| `git fetch` | Получить сведения и коммиты с сервера, не объединяя их с текущей веткой |
| `git merge` | Объединить изменения двух веток |
| `git push` | Отправить локальные коммиты или метки на сервер |

Запрос на объединение, или **pull request**, — это предложение перенести изменения из одной ветки в другую. В GitHub он позволяет посмотреть различия, обсудить изменения и выполнить объединение.
